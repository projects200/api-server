== 운동 이미지 업로드 API

=== 설명
- #POST# `/api/v1/exercises/{exerciseId}/pictures`
- 운동 기록에 이미지를 업로드하는 API입니다.
- 이 API를 통해 사용자는 운동 기록에 관련된 사진을 첨부할 수 있습니다.
- 사용자는 운동 기록 ID와 함께 이미지 파일을 업로드할 수 있으며, 이 API는 여러 이미지를 동시에 처리할 수 있습니다.

=== 오프라인 동기화 계약
- multipart의 `pictures` 파일 목록과 선택 폼/쿼리 `uploadRequestId` UUID,
  `clientImageIds` UUID 목록을 보냅니다. 두 메타데이터는 함께 생략하거나 함께 보내야 합니다.
- 동기화 배치는 파일 1..5개이며 이미지 UUID는 파일 순서와 1:1 대응하고 null/중복을 허용하지 않습니다.
  파일, 순서, 이미지 ID, 이름, content type, 크기 및 바이너리는 동일 키 재시도에서 불변입니다.
  변경한 요청은 400 `EXERCISE_REQUEST_ID_REUSED`입니다. 바이너리는 스트림으로 해시하며 DB에 보관하지 않습니다.
- 응답은 `exerciseId`, `version`, 요청 순서의 `pictures[{clientImageId,pictureId,pictureUrl}]`입니다.
  파일 이름/URL을 추정해 연결하지 마세요. 메타데이터 없는 기존 요청은 ID/버전을 반환하고 매핑은 생략합니다.
- 성공 영수증 재생은 삭제/현재 개수 제한 검사보다 우선합니다. 재시도는 새 사진을 만들지 않으며 원본 매핑을 반환합니다.
  새 업로드는 활성 사진 합계가 5개를 넘으면 400, 삭제된 운동이면 410 `EXERCISE_DELETED`입니다.
- 동기화 객체 키는 `uploads/exercise/{memberId}/{uploadRequestId}/{clientImageId}`입니다.
  DB 롤백(커밋 시 실패 포함)은 해당 시도에서 PUT을 시도한 객체 키만 정리합니다.
  정리는 회원 잠금 및 성공 영수증 확인으로 재시도에서 이미 커밋된 객체를 지우지 않습니다.

=== S3 장애와 고아 객체 운영 정책
- S3와 DB는 하나의 분산 트랜잭션이 아닙니다. 프로세스가 PUT 후 롤백 콜백 전에 종료되거나 롤백 객체 삭제도 실패하면 고아 객체가 남을 수 있습니다.
  안정적인 객체 키를 쓰므로 동일 요청 재시도는 같은 키를 덮어쓰며 추가 객체를 만들지 않습니다.
- 운영자는 이 prefix의 객체를 DB의 활성 Picture URL 및 성공 업로드 영수증과 대조한 뒤 참조되지 않는 객체만 정리합니다.
  prefix 전체 TTL 삭제나 활성 객체 선삭제를 하지 않습니다. 커밋된 사진 삭제의 장애는 영속 정리 큐가 재시도합니다.

=== 개발 참고 사항
- <<공통-개발-참고-사항,공통 개발 참고 사항>>을 참고하세요.
- 이 API는 multipart/form-data 형식으로 이미지를 업로드합니다.
- 요청의 필수 여부는 요청 파트(Form Data)의 필수 여부를 참고하세요.
- 요청에 대한 검증은 요청 파트(Form Data)의 설명을 참고하세요.
- 메타데이터 없는 기존 업로드의 객체 키는 기존 무작위 UUID 경로를 유지합니다.

==== 응답 상태 코드
|===
|상태 코드|설명
|201|운동 기록이 성공적으로 생성되었습니다.
|400|입력값 검증에 실패했습니다. 파일이 5개를 초과하거나 지원하는 확장자가 아닙니다.
|403|운동 기록이 회원의 운동 기록이 아닙니다.
|410|이미 삭제된 기록에 대한 새 사진 업로드입니다.
|500|이미지 업로드 중 서버 오류가 발생했습니다.
|===
