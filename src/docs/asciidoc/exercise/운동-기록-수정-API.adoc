== 운동 기록 수정 API

=== 설명

- #PATCH# `/api/v1/exercises/{exerciseId}`
- 이미지를 제외한 운동 기록 문자데이터 필드를 수정하는 API입니다.
이 API를 통해 사용자는 자신의 운동 기록을 수정할 수 있습니다.
- 사용자는 운동 제목, 종류, 장소, 상세 내용, 시작 시간, 종료 시간을 포함하여 운동 기록을 작성할 수 있습니다.
- 기존과 같이 전체 문자 필드를 보냅니다. 필수 제목/시작/종료 검증을 유지하며 선택 필드의 null은 해당 값을 비웁니다.

=== 오프라인 동기화 계약
- `editId` UUID와 0 이상의 `baseVersion`을 함께 보냅니다. 둘 다 생략한 기존 요청은 지원하지만 하나만 보내면 400입니다.
- 선택 `editedAt`은 사용자 저장 시 고정한 양수 UTC epoch 밀리초 정수이며 `editId`와 `baseVersion`이 필수입니다.
  0/음수 시각 또는 일부 메타데이터는 HTTP 400 `INVALID_INPUT_VALUE`입니다. 이미 캡처한 시각 없는 요청에 새 시각을 붙이지 않습니다.
- 요청과 서버 본문 모두 시각을 알면, 요청 `editedAt`이 엄격히 최신일 때만 수락합니다. 이 경우 오래된 `baseVersion`도 허용합니다.
  같거나 오래된 시각은 HTTP 409 `EXERCISE_EDIT_CONFLICT`이며 서버 본문을 유지합니다. 같은 시각의 다른 내용도 거절합니다.
- 서버 본문 시각이 NULL이거나 요청 시각이 없으면 기존 CAS를 유지합니다. `baseVersion`이 있으면 현재 서버 버전과 일치해야 합니다.
  서버 시각이 NULL인 행은 일치하는 CAS의 clocked 저장만 시각을 초기화합니다. 시각 없는 실제 본문 변경은 시각을 다시 NULL로 둡니다.
  메타데이터를 모두 생략한 기존 쓰기는 계속 지원합니다. 같은 본문의 시각 없는 no-op은 기존 시각과 버전을 유지합니다.
- 409 오류 `data`는 기존처럼 `exerciseId`와 현재 `version`뿐입니다. 최신 본문과 nullable `editedAt`은 상세 GET으로 확인합니다.
  충돌 뒤 새 요청을 만들 때는 확정 거절을 확인하고 새 `editId`를 사용합니다. 시각과 본문을 바꿔 과거 요청을 최신인 것처럼 만들지 않습니다.
- 같은 작업/대상/본문/기준 버전/시각의 `editId` 재시도는 현재 버전/삭제/시각 검사보다 먼저 원본 성공 응답을 반환합니다.
  같은 키에 다른 본문/기준 버전/시각/대상을 보내면 400 `EXERCISE_REQUEST_ID_REUSED`입니다.
- 삭제된 본문에 새 편집을 보내면 410 `EXERCISE_DELETED`입니다. 타인에게는 소유권 오류를 반환합니다. 오류 응답 형식은 유지합니다.
- 사진 추가/삭제는 버전만 변경하며 본문 `editedAt`을 변경하지 않습니다. 성공 응답은 기존 `exerciseId`, `version`입니다.
  시각이 더 최신인 본문 저장은 내용이 같아도 시각과 버전을 갱신합니다. stale base 수락 시 응답 버전은 `baseVersion + 1`보다 클 수 있습니다.
  본문 편집/날짜 이동은 기존 점수를 바꾸지 않습니다. 기기 시계 오차는 편집 순서 판정에 영향을 줄 수 있습니다.

==== 응답 상태 코드
|===
|상태 코드|설명
|200|운동 기록이 성공적으로 수정되었습니다.
|400|입력값 검증에 실패했습니다.
|403|운동 기록에 접근 권한이 없습니다
|404|운동 기록이나 회원이 존재하지 않습니다.
|409|본문 저장 시각이 같거나 오래되었거나, 시각 불명의 기준 버전이 다릅니다.
|410|이미 삭제된 기록에 대한 새 편집입니다.
|===
