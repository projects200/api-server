== 운동 기록 생성 API

=== 설명
- #POST# `/api/v1/exercises`
- 운동 기록을 생성하는 API입니다.
이 API를 통해 사용자는 자신의 운동 활동을 기록하고 관리할 수 있습니다.
- 사용자는 운동 제목, 종류, 장소, 상세 내용, 시작 시간, 종료 시간을 포함하여 운동 기록을 작성할 수 있습니다.
- 운동 기록 생성 시, 정책에 따라 점수가 부여됩니다.

=== 오프라인 동기화 계약
- 선택 JSON 필드 `createRequestId`는 UUID입니다. 생략하면 기존 v1 요청을 그대로 처리합니다.
- 같은 회원의 같은 키와 같은 의미의 본문은 최초 `exerciseId`, `earnedPoints`, `version`을 반환합니다.
  후속 수정/삭제 뒤에도 원본 응답을 재생하며 기록이나 점수를 다시 생성하지 않습니다.
- 같은 키를 다른 본문, 작업 또는 대상에 사용하면 HTTP 400 `EXERCISE_REQUEST_ID_REUSED`입니다.
  본문의 null과 빈 문자열은 다르며 클라이언트는 재시도 요청 본문을 바꾸면 안 됩니다.
- 생성의 초기 `version`은 0입니다. 본문/사진의 실제 변경과 삭제는 같은 회원 잠금 아래 버전을 증가시킵니다.
- 동기화 생성은 기록, 실제 회원 점수, 영수증을 한 DB 트랜잭션으로 저장합니다. 정책/DB 오류는 모두 롤백합니다.
  점수 확인 실패를 확정 0점으로 반환하지 않습니다. 메타데이터 없는 기존 생성의 점수 실패 시 기록 보존 동작은 유지합니다.
- 점수 기준은 기존 `exerciseStartedAt`과 서버 현재 시각에서 `EXERCISE_RECORD_VALIDITY_PERIOD`를 빼고 정책 단위로 내림한 경계입니다.
  유효 기간 밖의 지연 생성은 정상 0점입니다. 일일 횟수와 점수 상한도 그대로 적용합니다.
  날짜/본문 수정 및 기록 삭제는 이미 확정된 점수를 재계산하거나 회수하지 않습니다.

=== 스키마 적용 및 보존
- 배포 전에 백업 후 `documents/Undabang SQL/exercise_sync_upgrade.sql`을 한 번 적용합니다.
  기존 행은 보존되며 버전은 0으로 시작합니다. DROP TABLE을 포함하는 초기 설치 DDL을 업그레이드에 사용하지 않습니다.
- 영수증은 운동/사진 soft delete와 독립적으로 무기한 보존합니다. 회원 물리 삭제 시에만 함께 삭제됩니다.
  사진 정리 작업은 회원 삭제 뒤에도 남아 확정된 객체 삭제를 마칩니다.
